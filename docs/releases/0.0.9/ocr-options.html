Local handwriting, OCR, and image descriptions

A comparison of options that can keep working without a network connection. “OCR” covers several different jobs here, and the best fit depends on what the input is.

Scope constraint: recognition must be free to the user and run on the device. There must be no cloud inference or per-use charge. For disconnected use, the model must already be on the device; a first-use download is a setup requirement, not offline-from-install. Key distinction: stylus handwriting arrives as timed strokes; handwriting in photos needs image segmentation and HTR; describing a picture needs a vision-language model.

At a glance

Pen strokes → text

Digital ink recognition

Best match for notes written in the app. Mobile platforms have capable native options; language packs may need advance installation.

Photo or scan → text

Image OCR / HTR

Printed text OCR is mature. Handwritten page transcription is much less dependable and often needs line detection before recognition.

Picture → description

Image understanding

A local vision-language model can draft a caption or answer a question about an image. Results can be wrong and should be editable.

Image → searchable concepts

Embeddings

Local image embeddings can help find visually related material. They support similarity search; by themselves, they do not write a natural-language description.

Working proposal for NoteCraft

This is a discussion proposal, not an implementation decision. Keep recognition optional and preserve the original ink or image unchanged.

1 · Notes written with the pen

Recognize the stroke data

Use an on-device platform recognizer when its model is already available. Apple PencilKit is a strong iPad candidate. On Android, evaluate the open OnlineHTR research engine and compare it with ML Kit. ML Kit is no-cost and supports many languages, but its digital-ink language packs are dynamically downloaded and cannot be bundled through its documented installation paths.

Proposal: treat Android stroke recognition as an evaluation gap until a model can be provisioned without a network at use time, its model/data terms are clear, and it performs well on NoteCraft's scripts.

2 · Text inside photos and scans

Start with printed OCR

Use Apple Vision on Apple devices and ML Kit Text Recognition's bundled model on Android. These are on-device, have no per-call fee, and can be available without a runtime model download. Keep handwritten-photo recognition as a separate, later-quality question.

3 · Describing an image

Generate an editable draft

Use Apple's on-device Foundation Models on eligible devices. Evaluate Gemma 3n E2B on Android as a local multimodal candidate; also compare Apache-2.0 SmolVLM2 if its target-device runtime and model size are practical. Generate only when requested, and let the user accept, edit, or discard the description.

Free and offline distinction: ML Kit and OS frameworks have no per-request charge, but ML Kit Digital Ink still needs a language-pack download. “Free” also does not mean “open source”: Google and Apple platform SDKs are proprietary. If open model weights are required, verify both weight and training-data terms before bundling.

Decision points for the next ideation pass

  • Must the feature work on a fully disconnected fresh install, or is installing a model pack ahead of time acceptable?
  • Does “free” mean no user/API charge, or must the model and its weights also use an open-source license?
  • Which scripts are first-class for recognition quality, including Arabic, Persian, Urdu, Hebrew, and mixed RTL/LTR?

Practical takeaways

  1. For handwriting created in NoteCraft, start with the strokes. Keep ink as the original content. Recognition can generate a searchable or copyable text result without replacing the drawing.
  2. Plan model setup separately from offline use. “Runs offline” often means after a model has been downloaded or bundled. Offer a way to prepare models before a trip or in a no-network environment.
  3. Keep scan OCR and ink recognition as separate options. Stroke order helps digital-ink recognition; images need text detection, line segmentation, and image-based recognition.
  4. Describe pictures with an explicit, editable draft. Generated captions can miss context or make mistakes. Let the user accept, edit, or discard them.
  5. Check model and data rights independently. A permissive code license does not automatically grant commercial redistribution rights for weights or their training data.
  6. Give language coverage special scrutiny. Broad model language counts do not guarantee good handwriting recognition for a particular script, dialect, or writing style.
